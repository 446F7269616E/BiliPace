# BiliPace 威胁模型与隐私边界

## 范围与资产

范围包括三个浏览器产物、扩展页、content script、特权 background（Service Worker/事件页）、WebExtension storage/alarms/messages 和发布供应链。Bilibili、浏览器/操作系统、商店服务和承载 Safari 扩展的 app 是外部依赖。

需保护的资产：用户的设置/计划、聚合使用时长、临时放行状态、浏览活动隐私、扩展特权、更新渠道和发布凭据。

## 信任边界

```text
不可信 Bilibili 页面 DOM/脚本
          │ content-script 边界
          ▼
受限 content script ── runtime message ──► 特权 background
                                                │
                                                ▼
                                      extension local storage

源码/依赖 ── CI/build ── 商店签名/审核 ── 浏览器更新 ── 用户 profile
```

- Bilibili 页面及其 DOM、事件和任何注入数据均不可信。
- content script 与网页隔离世界不是安全认证；来自 content script 的消息仍可能由被攻陷页面/渲染器影响。
- background 与扩展页是特权区，但仍要防 DOM XSS、恶意/损坏 storage 和供应链代码。
- 本地 storage 不是对拥有浏览器 profile/设备访问权限的攻击者的加密保险箱；因此不应存敏感内容。

## 主要威胁与缓解

| 威胁                     | 影响                       | 必须缓解                                                      | 验证                        |
| ------------------------ | -------------------------- | ------------------------------------------------------------- | --------------------------- |
| 宽泛 host/API 权限       | 扩展被攻陷后可读取站外数据 | 只限必要 HTTPS Bilibili 子域；权限预算 gate                   | manifest 静态审计、安装警告 |
| 远程代码/依赖投毒        | 绕过商店审核或接管扩展     | 禁止远程代码/eval；锁依赖、可复现构建、审计 Actions           | 产物扫描、SBOM/依赖扫描     |
| 网页伪造消息触发特权操作 | 任意存储、导航、数据泄露   | 判别消息 schema、校验 sender/host/值域；无任意 URL/API        | 单元 fuzz、恶意页面测试     |
| DOM XSS / HTML 注入      | 扩展页或页面被执行恶意脚本 | `textContent`/安全 DOM API；禁止未消毒 `innerHTML`；严格 CSP  | 静态检查、payload E2E       |
| CSS/遮罩破坏站点         | 用户被锁死或页面不可用     | 扩展自有隔离命名/Shadow DOM（适用时）；可退出、安全降级       | DOM 变化、键盘退出测试      |
| 统计泄露过细             | 推断观看习惯/身份          | 统计只存日期+板块+秒；计划视频只由用户主动添加且完全本地      | storage 与网络审计          |
| 计划授权被扩大/重放      | 绕过计划模式浏览其他内容   | 授权绑定 itemId+BVID+绝对过期时间；变更、完成、删除即撤销     | 导航 E2E、边界单测          |
| 账号导入越权             | Cookie/账号或收藏内容泄露  | 当前 provider 不配置且不联网；仅允许未来官方 OAuth+服务端交换 | 代码/网络/权限审计          |
| 暴露扩展内部资源         | 网页读取内部实现或数据     | WARS 仅暴露 `plan.html`，只允许 Bilibili HTTPS 来源           | manifest 静态审计           |
| 心跳重放/重复标签        | 时长膨胀                   | 随机会话 ID、幂等序号、上限、明确多窗口口径                   | 重放/睡眠/多窗口测试        |
| 系统时钟/DST 操纵        | 绕过计划、负数或重复统计   | 单调差值、墙钟只做日历、重新计算 transition、校验非负         | fake clock + 手工边界       |
| storage 损坏/恶意导入    | 崩溃、原型污染、资源耗尽   | schema 校验、大小上限、普通对象复制、幂等迁移                 | corrupt/oversize fixtures   |
| 公开仓库/日志泄密        | 发布账号或用户数据泄露     | secret scan；最小日志；绝不提交签名资料/测试 profile          | CI + release 审计           |
| 发布账号接管             | 向全部用户推送恶意更新     | 强 MFA、最小发布者组、分支保护、签名 tag、审计记录            | 每次发布双人复核            |

## 隐私边界

首发允许处理：用户主动设置的屏蔽规则/计划、临时放行、主动加入观看清单的 BV 号/canonical URL/标题/顺序/完成状态、Bilibili 板块枚举、本地日期和聚合秒数。处理目的仅为本地屏蔽、计划执行、待办管理和仪表盘。

首发禁止收集或持久化：计划清单之外的完整 URL、视频/动态/用户 ID 或标题、搜索词、评论/消息、账号名、Cookie、认证信息、页面正文、站外浏览、设备标识或广告标识。禁止将允许数据发往开发者或第三方。

`chrome.storage.local`/等价 WebExtension storage 是唯一产品持久化边界；不使用 sync、远程备份或 analytics。用户清空后必须删除全部产品数据键及派生缓存。调试日志只能记录枚举/错误码，不记录原始 URL 或页面数据，生产默认关闭详细日志。

## 被接受但需说明的剩余风险

- Bilibili 改版可能让选择器/路由分类短暂失效；通过安全降级、集中规则和快速兼容发布降低影响。
- 浏览器/设备已被本地高权限攻击者控制时，本地设置和统计可能被读取或修改；数据最小化降低损失。
- 浏览器对窗口焦点、冻结和移动端后台事件的报告存在平台差异；仪表盘是帮助专注的近似值，不应宣称为审计级测量。
- Safari/Firefox API 生命周期与 Chromium 不同；平台候选验收不可被共享单元测试替代。

## 触发重新评审的变更

新增账户、同步、导入/导出、遥测、远程配置/API、AI、个性化推荐、其他站点、通知、新权限、跨设备数据或第三方 SDK 时，必须在实现前更新本模型和 `PRIVACY.md`，并重新评估商店显著披露/同意要求。
