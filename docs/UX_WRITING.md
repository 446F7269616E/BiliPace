# BiliPace 用户体验文案规范

> 状态：发布门禁（normative）  
> 适用范围：所有扩展页面、站内提示、错误、空状态、权限说明、README 与商店文案

## 目标

文案先帮助用户判断“现在发生了什么、下一步可以做什么”，再按需解释原因。界面不是实现文档，不向用户暴露内部数据模型、服务组件或维护流程。

## 必须遵守

1. 先写结果与可执行动作，一句话只表达一个决定。
2. 控件使用简短动词：`保存更改`、`开始观看`、`临时访问`；避免“执行、应用、配置”。
3. 错误使用“未完成的结果 + 下一步”，不得直接展示原始 `Error.message`、错误栈或内部代码。
4. 空状态说明可以获得什么，并给出就近入口；不得依赖“右侧、下方”等桌面布局位置。
5. 不责备、不制造内疚，不使用“浪费、戒断、无限浏览”等评价性表达。
6. 隐私先给短承诺“只保存在这台设备”，字段、权限和网络边界放到详情文档。
7. 尚不可用的能力说明用户结果与替代路径，不展示 provider、服务端、应用密钥、资质配置等实现词。
8. 状态不只靠颜色；可见文案、`aria-label` 和视觉状态必须一致。

## 统一术语

| 用户意图                 | 使用                    | 不使用                 |
| ------------------------ | ----------------------- | ---------------------- |
| 收起页面里的推荐、评论等 | 内容降噪 / 隐藏干扰内容 | 屏蔽策略 / DOM 过滤    |
| 到时不打开整个页面       | 专注拦截                | 元素屏蔽               |
| 短暂绕过整页规则         | 临时访问                | 临时放行               |
| 有目的的视频待办         | 观看清单                | 队列 / 计划项          |
| 时间统计页面             | 使用洞察                | 仪表盘（面向用户界面） |
| 一级全页入口             | 专注中心                | 控制台 / 后台          |

## 状态模板

- 加载：`正在准备你的观看清单` / `马上就好…`
- 成功：`更改已保存` / `已加入观看清单`
- 可恢复错误：`暂时看不到使用时间` + `请重试`
- 空状态：`还没有待看的视频` + `添加一个想看的视频`
- 不可用能力：`暂不支持账号导入` + `你仍可以批量粘贴视频链接`

## 评审清单

- [ ] 首屏能在五秒内看懂当前状态和主操作。
- [ ] 同一概念在 popup、专注中心、设置、观看清单和使用洞察中名称一致。
- [ ] 没有原始异常、内部模块名、数据 schema、服务端配置或开发路线图。
- [ ] 文案在窄屏、200% 缩放和读屏语义中仍完整。
- [ ] 删除或不可逆动作明确影响范围，并提供二次确认。
- [ ] 隐私承诺与 `PRIVACY.md`、权限和实际网络行为一致。
